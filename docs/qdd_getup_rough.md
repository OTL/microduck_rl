# QDD 二足：不整地の歩行と、転倒からの起き上がり

2026-10-17 に追加した課題が 2 つある。どちらもロボットは `docs/qdd_biped.md` と同じ。

| 課題 | 中身 | 実機での使い方 |
|---|---|---|
| `Mjlab-Velocity-Rough-QddBiped` | 不整地を歩く | 歩行と入出力が同じ（41 次元、`policy_io.json`）。`robot.toml` の歩行の `onnx` を差し替えるだけ |
| `Mjlab-Getup-QddBiped` | 転倒後の寝姿勢から立つ | 専用の入出力（36 次元、`policy_io_getup.json`、kind `getup`）。コントローラの `[getup]`：転倒 → 脱力 → 静止したら起き上がり → 立つ → 歩行 |

## 不整地の歩行（`tasks/qdd_biped_rough_env_cfg.py`）

平地の歩行（gait4）と同じ設定に、次のものを足した。

- **地形**：1 枚 5 m 四方。難しさ 10 段階 × 種類 6 列（カリキュラム）。

| 種類 | 割合 | いちばん難しい段 |
|---|---|---|
| 平地 | 10 % | — |
| 凸凹（ハイトフィールド、10 cm 間隔） | 25 % | 高低差 4 cm |
| 坂（ピラミッド） | 20 % | 15° |
| 段差（ピラミッドの階段、踏み面 30 cm） | 20 % | 5 cm |
| 石畳（35 cm の箱、高さがばらばら） | 15 % | 3 cm |
| 波 | 10 % | 振幅 4 cm |

- **段の上げ下げ**：`mdp.qdd_terrain_levels_survival`。1 回分（20 秒）を転ばずに歩き切り、速度のずれの平均が 0.2 m/s 未満なら 1 段上げ、転んだら 1 段下げる。最初は下から 3 段までに置く。（1 回目の rough1 では mjlab の `terrain_levels_vel`（2.5 m 以上離れたら上げる）を使ったが、このロボットは遅く指令もよく変わるので平地でもほとんど上がらず、平地 0.46・階段 0.37 段で終わった。）
- **方策（actor）は見えないまま**。高さの地図は critic だけに入れる（胴体のまわり 0.8 × 0.5 m）。そのため実機は今の歩行と同じ入出力で動く。
- **足の高さ**：遊脚の高さ、最低クリアランス、足裏を平らにする項は、地面からの高さで測る。足裏の 5 cm 上から下に光線を出す（`sole_clearance_scan`）。足裏から出すと、足が少しめり込んだときに地面の中から出ることになり、坂で地面に当たらなかったため。
- **feet_flat** を −2.0 から −0.5 に弱めた。15° の坂では、立脚の足裏も 15° 傾くのが正しいため。
- ソルバの反復を 10 → 20 回、接触の上限を 120 に増やした（箱の角での NaN を防ぐため）。
- 学習の回数は既定で 3000 回。play では難しさ 0.3〜1.0 の 4 段。

## 転倒からの起き上がり（`tasks/qdd_biped_getup_env_cfg.py`）

### 始める姿勢：転倒後の寝姿勢のライブラリ

`scripts/qdd_getup_states.py` で作った `robot/qdd_biped/getup_states.npz`（3000 通り）。素の MuJoCo で、**今のコントローラで実際に起きる転び方**をシミュレーションし、止まるまで待った姿勢を集めた。

- push（44 %）：既定の姿勢で立っているところを、0.8〜2.0 m/s で押す。転倒の判定（傾き 35° 超かつ角速度 3 rad/s 超、または傾き 50° 超）までは PD で姿勢を保ち、判定のあとは脱力（Kp 0、Kd 0.5）して倒れる。
- stride（32 %）：歩いている途中の姿勢（関節 ±0.35 rad、胴体の傾き最大 15°）から、0.3〜1.5 m/s で押す。
- drop（23 %）：向きも関節角もばらばら（膝は `knee_max` 以内）で、高さ 0.45 m から脱力したまま落とす。
- 止まった姿勢だけを残す。倒れなかったもの、関節範囲を外れたもの、`knee_max` を 0.1 rad 超えたものは捨てる。胴体の傾きは中央値で約 100°（うつ伏せ・あお向け・横向き）。

リセットでは、ライブラリから 1 つ選んで向き（ヨー）だけを乱数にする。10 % は立った姿勢から始める（立ち続けることも覚えさせる）。

### 当たり判定

寝ている姿勢では、どの部品が床に当たるかと摩擦が大事なので、歩行用とは別の当たり判定にした（`get_qdd_biped_getup_robot_cfg`）。

- 歩行用の当たり判定（胴体の箱、腿・すねのカプセル、膝の球）に摩擦を付けた（condim 3、0.6。起動時に 0.3〜1.0 で乱数化）。
- モータのハウジング（股のヨー・ロール・ピッチ、膝、足首の円柱）と、胴体の上のウサギの部分（箱）を足した。これらは床にだけ当たる（脚どうしの自己衝突の判定は歩行と同じ）。
- 入れていないもの：ウサギの耳（TPU で曲がる）と、カバーの正確な形（roll_cap、shell_bumper_rear、knee_pad、shank_cover）。学習のあと、ロボットのリポジトリの CAD メッシュの当たり判定（`analysis/fall_sim.py` と同じもの）で確かめること。

### 観測・行動

- actor は歩行の観測から指令と歩容クロックを除いた 36 次元：角速度、重力の向き、関節角、関節速度、前回の行動。ノイズ・遅れ・IMU の取付誤差・エンコーダの零点ずれは歩行と同じ。
- 行動のスケールは 0.5 rad（歩行は 0.25）。起き上がりでは関節の範囲をいっぱいに使うため（股ピッチ −100°、膝 120°）。Kp/Kd は歩行と同じ。
- critic には、胴体の高さ、並進速度、足以外が床に当たっているかを足した。
- 左右反転の損失：歩行の表の先頭 36 個をそのまま使う。

### 報酬

| 項目 | 重み | 内容 |
|---|---|---|
| getup_progress | +20 | ポテンシャル型：Φ = (1 + cos 傾き)/2 + 胴体の高さ（0.05 m で 0、立った高さで 1）。毎ステップ ΔΦ を払う。起き上がると得、倒れ直すと同じだけ損。その場にいても何ももらえない（稼げない） |
| standing | +3 | 立っていること：直立（exp(−(1−cos 傾き)/0.05)）× 高さ（立った高さとの差、std 6 cm）× 足の接地（0.5 + 0.5 × 接地している足の割合）の積 |
| stand_still | +1 | 立っているとき（standing > 0.5）だけ：胴体が止まっていること |
| stand_pose | +1.5 | 立っているときだけ：関節が既定の姿勢に近いこと（歩行へ渡すため） |
| torso_ang_vel | −0.5 | 胴体の角速度が 4 rad/s を超えた分の 2 乗（振り回して起きるのを防ぐ） |
| body_impact | −0.5 | 足以外の部品が床を押す力が 150 N を超えた分（150 N で割る）（叩きつけて起きるのを防ぐ） |
| action_rate_l2 | −0.01 → −0.06 | 1000 回、2000 回で強める（動きを見つけるまでは弱く） |
| joint_torques, dof_pos_limits, self_collisions, knee_limit | 歩行と同じ | |

悪い状態（寝ている、膝をついている）に対しては何も払わない。これは AGENTS.md の「悪い状態で正の報酬を払わない」に従っている。道筋（キーフレーム）も与えない。

### 終了条件

時間切れ（8 s）、NaN、膝が `knee_max` を 0.3 rad 超えた。倒れたことでは終わらない。

### 実機への受け渡し（`policy_io_getup.json` の `getup`）

- 始める条件：脱力した状態で、胴体の傾きが 30° 超、角速度 0.3 rad/s 未満が 1 s 続いた。
- 終わる条件：傾き 12° 未満、どの関節も既定の姿勢との差が 0.25 rad 未満、角速度 0.5 rad/s 未満が 0.5 s 続いた。終わったら立った姿勢を保ち、歩行の方策に渡す。

作り直し：

```
uv run python scripts/qdd_getup_states.py --n 3000
uv run python -m mjlab_microduck.tasks.qdd_biped_getup_env_cfg   # policy_io_getup.json
```

### わかっていないこと

腕が無いので、すべての寝姿勢から起き上がれるか（特にあお向け）は、学習してみるまでわからない。`Metrics/getup_stood_frac`（立てている環境の割合）を見る。

## 学習の出し方（yatai）

```
python3 rl/yatai_launch.py --via-server --task Mjlab-Getup-QddBiped --ref <このブランチ> --envs 4096 --iters 3000 ...
python3 rl/yatai_launch.py --via-server --task Mjlab-Velocity-Rough-QddBiped --ref <このブランチ> --envs 4096 --iters 3000 ...
```

先に試運転（`--envs 64 --iters 5`）をする。CPU での 1 回あたりの時間は、平地の歩行に比べて起き上がりが約 1.0 倍、不整地が約 1.3 倍だった。

## テスト

`tests/test_qdd_getup.py`（CPU）：当たり判定、寝姿勢のライブラリ、報酬の符号、policy_io と実際の環境の一致、リセットで寝姿勢になること、立っているロボットの報酬が満点に近いこと、ポテンシャル型の報酬、不整地の 6 種類すべてで立ったときの足裏の高さが 0 になること。
